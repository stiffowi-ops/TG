# Telegram Mini App «Локации»

Изолированный проект на Go + React/TypeScript, адаптированный для Bothost. Клиентский интерфейс: **каталог + карта**, оранжевый/белый/графит, сбалансированная плотность. Рабочий репозиторий `stiffowi-ops/Karty` не изменяется.

## Реализовано

- Каталог **114** исходных локаций и **104** подтверждённых координат, индивидуальные ссылки на Яндекс Карты, поиск и фильтры. Если координаты неизвестны, приложение не подставляет вымышленные.
- Карточка с ориентиром, статусом, трафиком, аудиторией, возможностями и выводом. Данные исходного Karty перенесены копированием Go-модулей и встроенных файлов.
- Избранное на сервере по Telegram ID, сравнение 2–3 локаций, история и статусы заявок.
- Реальное создание заявок, валидация телефона `+7` + 10 цифр, до двух дополнений, управление состояниями «Получено», «В работе», «Решено».
- Таймер завершения через 60 минут после взятия в работу, уведомления и напоминания Karty с учётом рабочих окон из перенесённого Go-модуля.
- **Админка только для `ADMIN_IDS`**: банк заявок, принятие и завершение, подтверждение дополнений, аналитика, посетители, редактор карточек, добавление локаций, скачивание ZIP-бэкапа.
- Публичный Go API открывает каталог; **все пользовательские и администраторские API требуют подписанное `Telegram.WebApp.initData`**, проверенное на сервере HMAC. ID из браузерного ввода не принимается.
- Один Go-процесс одновременно обслуживает HTTP и Telegram long polling; второй тестовый Telegram-процесс запускать нельзя.

## Переменные окружения Bothost

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | **Токен отдельного тестового бота** из BotFather (Bothost часто назначает его автоматически) |
| `ADMIN_IDS` | **Обязательно для заявок и админки.** Числовые Telegram ID администраторов через запятую, например `123456789,987654321` (это только примеры) |
| `MINIAPP_URL` | `https://myloc.bothost.tech` (без `/webhook`), либо задаётся из `DOMAIN` |
| `PORT` | `8080` |
| `DATA_DIR` | `/app/runtime`, задано в Docker; важно сохранять каталог между перезапусками |

Параметры сервиса: GitHub `https://github.com/stiffowi-ops/TG.git`, ветка `main`, Dockerfile `Dockerfile`, веб-порт `8080`, публичный HTTPS-домен. В BotFather или переменной MINIAPP_URL используется корень HTTPS-сайта. Никакие секреты не добавлять в GitHub или frontend.

Если Bothost подставляет `BOT_TOKEN` автоматически, не нужно дублировать. Если `ADMIN_IDS` пустой, **админка никому не показывается и отправка заявок отключена**. Вносить туда `@username` нельзя, нужны числовые Telegram ID.

## Проверка

1. `https://myloc.bothost.tech/api/health` возвращает JSON с `ok:true`.
2. `https://myloc.bothost.tech/api/locations` возвращает полный каталог из 114 локаций (не считая добавленных администратором).
3. В Telegram тестовому боту отправить `/start`, нажать «Открыть приложение».
4. Аккаунт из `ADMIN_IDS` видит «Управление», обычный аккаунт не видит.
5. Проверить тестовую заявку, получение Telegram-уведомления администратором, принятие в работу, дополнение и завершение.

Локально для API: `go test ./...`, `go run ./cmd/server`; для UI: `cd web && npm install && npm run dev`. Для Docker: `docker build -t miniapp .`, затем `docker run --rm -p 8080:8080 -e PORT=8080 -e DATA_DIR=/tmp/demo miniapp` для просмотра каталога без Telegram.

## Изоляция и остаток работ

Новый бот использует **только свой тестовый токен и отдельные файлы в `DATA_DIR`**. Подключение к живой базе или существующим клиентским заявкам рабочего Karty не выполнялось. Текущие рабочие заявки и фотографии с продакшен-сервера сами не появятся.

Go-модули рабочей логики и резервных копий перенесены, но **не все старые админские инструменты доступны как экран Mini App**: восстановление ZIP, массовая чистка, подробная история редактирования, синхронизация фотографий и расширенные служебные операции остаются задачами дальнейшего интерфейсного переноса. Их нельзя считать реализованными только потому, что код модуля присутствует.

До переключения пользователей на новую версию нужна отдельная проверка на Bothost: зелёная GitHub-сборка не гарантирует корректную выдачу домена, сохранение файлов между деплоями или доставку Telegram-сообщений.
