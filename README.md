# Mini App · прототип подбора локаций

Отдельный экспериментальный проект. **В интерфейсе не используется техническое имя проекта.** Рабочий Telegram-бот и его репозиторий не изменяются.

## Что работает в прототипе

1. **Каталог:** карточки, поиск с `ё`/`е`, фильтрация по типу и району, обзорная карта, переходы на Яндекс Карты, окно локации. Фото поддерживаются через `imageUrl` в `/api/locations`. Пока настоящие фото не перенесены, показывается честно обозначенная демо-иллюстрация.
2. **Избранное:** добавление и удаление, хранение только в браузере, сравнение двух или трёх локаций.
3. **Заявки и история:** демонстрационные статусы «Получено», «В работе», «Решено», ознакомительная форма с вопросом о сотрудничестве, контактах и выборе локации, добавление максимум двух дополнений, история по времени. Никакие заявки на сервер не отправляются.

В Go API доступен **только чтение каталога**. Подключений к настоящим заявкам, админке, авторизации, общей БД или старому боту нет. Телефон и имя в демо-форме используются для отображения шага проверки, **не сохраняются** и не отправляются.

## Структура

- `web/` — React + TypeScript + Vite, клиентское Mini App.
- `cmd/server/` — Go HTTP API + раздача собранного интерфейса.
- `internal/demo/` — отдельная копия нескольких названий и координат для теста. Данные только демонстрационные.
- `cmd/testbot/` — минимальный отдельный тестовый Telegram-бот, отправляющий кнопку запуска Mini App по `/start`.

## Локальный запуск

Требуется Go 1.23+, Node.js 22+, npm. Откройте **два терминала** из корня проекта:

```bash
# Терминал 1. Go API
 go run ./cmd/server
```

```bash
# Терминал 2. Интерфейс
 cd web
 npm install
 npm run dev
```

Откройте `http://localhost:5173`. Vite автоматически передаст `/api/locations` на Go `:8080`. Можно смотреть и в обычном браузере без Telegram. При ошибке API показываются встроенные демонстрационные точки.

### Единый сервер для публикации

```bash
cd web && npm install && npm run build && cd ..
WEB_DIST=web/dist ADDR=:8080 go run ./cmd/server
```

Или Docker: `docker build -t locations-demo . && docker run -p 8080:8080 locations-demo`.

**Важно:** перед подключением Telegram сервер должен быть доступен по публичному HTTPS-домену. Голый localhost для реального Mini App не подходит. Можно использовать отдельный поддомен и HTTPS reverse proxy.

## Отдельный Telegram-бот

1. Создайте нового бота в [@BotFather](https://t.me/BotFather), не используйте токен действующего бота.
2. Опубликуйте frontend+backend по HTTPS, например `https://mini.example.com`.
3. Запустите отдельный процесс (в любом окружении, где доступен Go и сеть):

```bash
export TEST_BOT_TOKEN='токен_НОВОГО_бота'
export MINIAPP_URL='https://mini.example.com'
go run ./cmd/testbot
```

Тестовый бот установит для **себя** кнопку меню «Открыть приложение», а по `/start` отправит сообщение с кнопкой `web_app`. Его токен нельзя добавлять в репозиторий или frontend.

## Безопасность и границы

- Демо-заявки и избранное хранятся в `localStorage` **текущего браузера**. Они не синхронизируются между устройствами. Никаких реальных сообщений админу нет.
- Образцы заявок со статусами «В работе» и «Решено» только иллюстрируют интерфейс; их таймеры не действуют. Реальная логика двух дополнений, уведомлений, часового автозавершения и рабочих часов находится **только в существующем боте**, который здесь не вызывается и не изменяется.
- `initDataUnsafe` из Telegram нельзя использовать как подтверждение личности на сервере. Перед любым настоящим серверным действием с данными пользователя необходимо верифицировать подписанный `Telegram.WebApp.initData` на backend и ограничить доступ по проверенному ID. Здесь таких действий нет.
- Не добавляйте сюда секреты, персональные данные клиентов или конфигурацию рабочего бота.
- Подписи к фотографиям должны соответствовать реальным локациям. Пока фотографий нет, интерфейс явно говорит, что это демо-иллюстрации.

## Размещение в новом GitHub-репозитории

Создайте **пустой отдельный репозиторий**, например `mini-app-locations`, без стартового README, и загрузите файлы этого архива. Из корня распакованного проекта:

```bash
git init
git add .
git commit -m "Initial isolated Mini App prototype"
git branch -M main
git remote add origin https://github.com/<your-user>/mini-app-locations.git
git push -u origin main
```

Если репозиторий создан с готовым README, проще загружать через веб-интерфейс GitHub или выполнить аккуратное слияние, а не переписывать историю.
