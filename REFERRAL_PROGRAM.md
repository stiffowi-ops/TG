# Реферальная программа TG

## Клиент
- Любому авторизованному пользователю генерируется уникальный случайный реферальный код (96 бит). Код сохраняется в `leads.json`, не меняется после перезапуска.
- В «Профиль → Бонусы» находятся персональная ссылка, «Скопировать», «Поделиться», количество приглашений на проверке и начислений.
- При переходе по ссылке Telegram передаёт подписанный `start_param`. Сервер проверяет `initData` и записывает приглашение по Telegram ID; код переносится в заявку даже при переходе сразу из главного меню.
- В заявке есть «У вас есть реферальная ссылка?» Да/Нет и поле ввода ссылки/кода. Кнопка «Нет» отменяет даже автоматически захваченную ссылку.
- Реферальное приглашение считается только после успешного сохранения первой заявки. Самоприглашения, неверные коды, подмена уже закреплённого приглашения и повторное начисление за того же Telegram-пользователя запрещены.

## Администратор
- Карточка заявки в Telegram и Mini App показывает пригласившего и статус реферального решения.
- «Взять в работу» работает независимо от реферальной программы и запускает прежний часовой срок выполнения.
- После принятия заявки появляются «Начислить 10%» и «Назначу позже». При «Назначу позже» пригласившему **ничего не отправляется**; назначившему администратору приходит напоминание.
- В Mini App администратор видит отдельный раздел «Реферальные начисления» с ожидающими и отложенными вознаграждениями. Начислить можно и после автоматического закрытия заявки.
- При начислении результат сохраняется в `leads.json`. Отдельный доставщик отправляет пригласившему сообщение с кнопкой «Перейти в профиль». Успешная доставка записывается, неуспешная повторяется после восстановления доступа.
- Ручная скидка и реферальная скидка хранятся отдельно: показываемый процент равен **максимальной** из двух, а не сумме. Кнопка «Воспользоваться скидкой» резервирует выбранное начисление. Администратор подтверждает списание в разделе «Запросы на скидку» или в личном чате бота. Обе кнопки подтверждают один запрос. Клиент видит историю в профиле и получает сообщение с кнопкой перехода в профиль. При равных процентах сначала используется реферальное начисление. Другие начисления доступны для следующих оплат.

## Настройка прямых ссылок в Telegram

Рекомендуется настроить в **@BotFather** основное Mini App для того же Telegram-бота и URL, что используется в `MINIAPP_URL`. После этого ссылки вида `https://t.me/<bot_username>?startapp=ref_...` откроют Mini App с кодом.

Если Mini App зарегистрировано как **именованное** с коротким именем, задайте переменную окружения `REFERRAL_MINIAPP_SHORT_NAME` (именно short_name из @BotFather). Тогда ссылки будут вида `https://t.me/<bot_username>/<short_name>?startapp=ref_...`.

Опционально `REFERRAL_BOT_USERNAME` может указать имя бота до первого успешного getMe; обычно оно определяется автоматически. Не добавляйте @ в значение.

Для кнопки «Перейти в профиль» используется `MINIAPP_URL?view=profile`; при отсутствии URL применяется прямая ссылка `startapp=profile`.

**Важно:** Telegram разрешает боту писать пользователю только при наличии доступа к личному чату. Если сообщение с наградой временно невозможно доставить, начисление сохранится, а отправка будет повторена. Не полагайтесь на успешную отправку как на факт начисления.

## API и данные
- `GET /api/referral`: текущая персональная ссылка, код, текущая привязка и счётчики.
- `POST /api/referral/validate`: проверка кода для авторизованного пользователя.
- `GET /api/me`: дополнительный `referralCode`.
- `POST /api/cases`: поле `referralCode` и `skipReferral`.
- `GET /api/admin/referrals`: очередь решений администратора.
- `POST /api/admin/referral`: `{number,action:"award"|"defer"}`.

Приглашения, коды и решения сохраняются вместе с заявками в `leads.json`; используйте существующие резервные копии. В БД сохраняется подтверждение успешной отправки Telegram-уведомления. Существующие заявки без реферальных полей остаются совместимыми.

## Проверки
Тесты в `internal/telegram/referrals_test.go` проверяют самоприглашение, повторные награды, приоритет ручной скидки, отложенное начисление после закрытия, восстановление из файла, авторизацию администратора и отказ от ссылки. Browser test в `scripts/check-telegram-layout.cjs` проверяет реферальный раздел, ссылки и автоматическое заполнение поля.
