# Яндекс Карты и фотографии: настройка Bothost

## Фотографии из Яндекс Диска

Папка: https://disk.yandex.ru/d/TpiMfBy9WROTGg

Публичный API Яндекс Диска вернул 342 файла. Проверенный формат имени:
`001 Метро Остров Мечты — 1.jpg`, `001 Метро Остров Мечты — 2.jpg`, `001 Метро Остров Мечты — 3.jpg`.
Исправлена обработка длинного тире (`—`) и префиксов номеров локаций.
Для скачивания Яндекс выдаёт одноразовый URL на `downloader.disk.yandex.ru`, который наш загрузчик поддерживает.

После обновления контейнера фотографии начинают синхронизироваться при запуске приложения.
Периодический повтор раз в 12 часов. Ожидание первой синхронизации зависит от скорости сети Bothost и количества файлов.

Для диагностики: Telegram Mini App → **Управление → Фото** → «Обновить статус».
Если кнопка недоступна, проверьте `ADMIN_IDS`. Используется тот же действующий тестовый Telegram-бот.

Фотографии сохраняются отдельно в `DATA_DIR/location_photos` (обычно `/app/runtime/location_photos`).
Папка должна сохраняться между развёртываниями.

## Яндекс Карты JS API v3

Официальный API карты требует собственный публичный ключ JavaScript API с ограничением
по HTTP Referer. Получите его в [кабинете разработчика Яндекс Карт](https://developer.tech.yandex.ru/).

В окружении Bothost задайте:

```
YANDEX_MAPS_API_KEY=ваш_публичный_ключ_js_api
```

В настройке ключа обязательно разрешите домен вашего Mini App, например `myloc.bothost.tech`.
Не заменяйте этим параметром `MAP_CONSTRUCTOR_ID`, который нужен другому функционалу.

Ключ доступен браузеру из `GET /api/map/config`, как требует JavaScript API.
Это **не секретный серверный ключ**: защитите его Referer-ограничением на стороне Яндекса.
Если ключа нет или Яндекс не загрузился, показывается существующая Leaflet-карта.
Это позволяет тестировать приложение без платного API и избежать белого экрана при ошибках сети.

Из-за условий Яндекса убедитесь, что выбранный тариф подходит для коммерческого каталога.
Официальная документация: https://yandex.ru/maps-api/docs/js-api/common/quickstart.html
